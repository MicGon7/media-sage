# MS-9: Room Database Schema (Entities, DAOs)

**Epic:** MS-2 (Shared Data Layer)
**Date completed:** 2026-04-17

## What was built

Room database schema in the shared KMP module with four entities, four DAOs, type converters, database class, and platform-specific builders.

### Entities
- **FigureEntity** — theologians, mystics, modern figures, biblical figures. Fields: name, category, century, description.
- **QuoteEntity** — quotes attributed to figures. FK to FigureEntity. Fields: text, source, themes (comma-separated tags).
- **HeadlineEntity** — cached news headlines. Fields: title, source, url, imageUrl, publishedAt, fetchedAt (both epoch millis).
- **MatchEntity** — AI-matched headline-to-quote pairs. FK to HeadlineEntity and QuoteEntity. Fields: explanation, confidence, connectionThemes, createdAt.

### DAOs
Each DAO has insert (single + batch), query (by ID, by relationship, all with Flow), and delete operations.

### Infrastructure
- **Converters** — `List<String>` ↔ comma-separated String for theme tags.
- **MediaSageDatabase** — `@Database` class with `@ConstructedBy` for KMP support.
- **Platform builders** — Android uses `context.getDatabasePath()`, iOS uses `NSHomeDirectory()`.

## Key decisions & why

- **Epoch millis for dates**: Stored `publishedAt`, `fetchedAt`, `createdAt` as `Long` (epoch millis) instead of using a date type. Avoids type converters for dates and works across all KMP targets without platform-specific date handling.
- **Comma-separated strings for themes**: Stored theme lists as comma-separated strings instead of a separate junction table. Simpler schema for now — themes are for display and AI matching, not for complex querying. Can migrate to a proper many-to-many relationship later if needed.
- **Single category for figures**: Each figure gets one category (theologian/mystic/modern/biblical) even though some span multiple. This is for UI grouping, not theological accuracy. Claude's matching engine works on quote content and themes, not categories.
- **ForeignKey with CASCADE delete**: Deleting a figure cascades to its quotes, deleting a headline cascades to its matches. Prevents orphaned records.
- **Flow return types on DAOs**: Query methods return `Flow<List<T>>` for reactive UI updates. Single-item lookups return suspend functions.

## Concepts learned

- **`@ConstructedBy` in KMP Room**: Non-Android platforms need a `RoomDatabaseConstructor` to instantiate the database. You declare an `expect object` in commonMain and KSP generates the `actual` implementations per target.
- **`@Suppress("NO_ACTUAL_FOR_EXPECT")`**: Required because the actual implementations are generated by KSP, not written by hand. The compiler would otherwise complain about missing actuals.
- **Schema export**: `exportSchema = true` + `schemaDirectory("$projectDir/schemas")` in build.gradle.kts generates JSON schema files. These are used for migration testing and schema verification.
- **Platform database builders**: Android needs a `Context` to locate the database file. iOS uses `NSHomeDirectory()`. This is the main KMP difference from standard Android Room.

## Gotchas

- **`@ConstructedBy` required for KMP**: Without it, builds fail on iOS targets with "The @Database class must be annotated with @ConstructedBy since the source is targeting non-Android platforms."
- **`RoomDatabaseConstructor` interface**: The `expect object` must explicitly override `initialize()` — simply extending the interface isn't enough. The error message is misleading ("not abstract and does not implement abstract member").
- **DAO unit tests deferred**: Room DAO tests require an in-memory database which needs platform-specific setup (Android instrumented tests or Robolectric). Deferred to a future integration test ticket rather than blocking the schema definition.
