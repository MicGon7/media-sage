# MS-121: Pinned Figure Home Screen — Daily Devotional Briefing Card

## What Changed

Added a "briefing card" to the top of the Home screen. Users pin a figure from its detail screen; the card displays that figure's portrait (sepia-filtered), a morning or evening devotional reflection generated by Claude, and the verified quote sources the reflection drew from. The reflection is grounded exclusively in the figure's seed quotes — Claude cannot hallucinate quotes that don't exist.

## Key Decisions

**BFF (Backend-for-Frontend) pattern for quote access.** The client sends `POST /api/analysis/daily-reflection` with `{ figureId, figureName, headlines, tone }`. The server fetches verified quotes from Supabase (via `QuoteRepository`), scores them by theme overlap with the headline titles in Kotlin, takes the top 5, builds a grounded Claude prompt, and returns the structured reflection. The client never touches the quote corpus directly.

**Theme scoring in Kotlin, not SQL.** With ~10 quotes per figure, a SQL `LIKE` join would be more brittle than a Kotlin word-overlap count. The scoring function lowercases both the quote themes and the headline words, filters tokens shorter than 4 characters, and sorts by overlap count descending. This is simple, readable, and runs in microseconds on a small set.

**Claude is constrained to verified quotes only.** The system prompt instructs Claude to draw only from the provided quote pool and lists each quote with its source title. The user message ends with a strict JSON schema. This is a lightweight RAG pattern — not embeddings, just prompt engineering with a validated corpus.

**Cache key: `${figureId}_${epochDay}_${tone}`.** `epochDay = currentTimeMillis() / 86400000L`. The cache is hit at most twice per day per pinned figure (once per tone). `DailyReflectionEntity` is a Room table with this composite key as a string `@PrimaryKey`. On cache hit, the card renders immediately with no server call.

**Tone derived from local hour.** `(epochMillis() % 86400000L / 3600000L).toInt() < 12 → "morning"`, else `"evening"`. This is intentionally UTC — simple and consistent across timezones for now.

**`currentTimeMillis()` is `internal` in shared.** The existing `currentTimeMillis()` expect/actual function has `internal` visibility, so `composeApp` can't call it directly. A thin public wrapper `fun epochMillis(): Long = currentTimeMillis()` in `TimeUtils.kt` (same package) exposes it without breaking the module boundary.

**Single-row Room entity for pinned state.** `PinnedFigureEntity` uses `@PrimaryKey val id: Int = 1` — the "singleton row" pattern, the same approach used for `SyncMetaEntity`. The DAO has `observe(): Flow<PinnedFigureEntity?>` so `HomeViewModel` reacts immediately when the user pins or unpins a figure from `FigureDetailScreen`.

**Sepia filter via Compose `ColorFilter`.** The figure portrait uses `ColorFilter.colorMatrix(sepiaMatrix)` applied to an `AsyncImage`. The sepia `ColorMatrix` is a 4×5 affine transform on RGB channels (same weights used by CSS sepia filter). This preserves the newspaper/etching aesthetic without any image processing on the server.

**`BriefingCardState` sealed interface on `HomeContract.Success`.** Three states — `Hidden` (no pinned figure), `Loading` (fetch in progress), `Ready` (data available). `HomeViewModel` launches `loadBriefingCard()` independently from headline loading in `init`. The `updateBriefingCard()` helper copies the current `Success` state — if headlines haven't loaded yet, the update is a no-op (guard: only runs when state is `Success`).

**Pin button in `FigureDetailScreen` header.** `Icons.Outlined.PushPin` / `Icons.Filled.PushPin` toggled by `isPinned: Boolean` on `FigureDetailContract.UiState.Success`. `FigureDetailViewModel` observes the pinned state independently via a `collect` coroutine and updates the UI state. `PinToHome` intent calls `setPinnedFigureId(figureId)`, which is a toggle — if the figure is already pinned, it sets to the same ID (idempotent). Unpinning requires calling with `null`, which would be a separate intent if needed later.

## What I Learned

**The "singleton row" pattern in Room.** Storing a single mutable value (like the pinned figure ID) in a Room table with `@PrimaryKey val id: Int = 1` and `OnConflictStrategy.REPLACE` on upsert is idiomatic for KMP. It's observable via `Flow`, survives app restarts, and requires zero migration complexity compared to shared preferences or DataStore.

**`internal` visibility in KMP shared modules.** `expect`/`actual` functions in shared KMP modules often use `internal` to prevent leaking platform-specific implementations. When `composeApp` needs to call one, the cleanest fix is a thin public wrapper in the same package — not bumping visibility on the original.

**Detekt `LongMethod` fires at exactly 30 lines.** The limit is inclusive. Extracting a multi-line string literal into a `companion object` constant is the cleanest fix — it reduces the method body without changing any logic.

**BFF theme scoring is idiomatic at small scale.** The decision not to use SQL `LIKE` for theme matching was deliberate — with 5–10 quotes per figure, a Kotlin word-overlap sort is more readable, testable, and maintainable than a SQL expression. The optimization tradeoff only reverses at hundreds of quotes per figure, which is not a current concern.
